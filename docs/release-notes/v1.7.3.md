# v1.7.3 — OpenCode Zen Free Quota Handling

## Summary

v1.7.3 is an urgent provider-reliability patch for OpenAI-compatible providers, with specific handling for OpenCode Zen free-model completion limits.

## Fixed

- Detects OpenCode `FreeUsageLimitError` from top-level and nested error payloads.
- Stops retrying when a provider reports exhausted free completion quota; retries are reserved for transient rate limits and network failures.
- Keeps the provider-reachable state separate from completion-quota state, so a valid key is not reported as an authentication failure.
- Includes OpenCode Zen guidance to try another available free model or wait for the provider window to reset.
- Preserves the existing masked-key policy and never returns API keys to clients.
- Adds regression coverage for nested OpenCode error shapes and quota-specific messaging.

## User action

After updating to v1.7.3, open **Settings → Local model**, confirm the Base URL and Model ID, then use **Test connection**. If OpenCode reports that the selected free model has exhausted its completion quota, switch to another available model or wait for the free window to reset. Rotate any API key that was shared in chat or another public location before using it again.

## Compatibility

This is a backward-compatible patch release. Existing local settings and stored task data are preserved.
