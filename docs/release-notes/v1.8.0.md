# v1.8.0 — Trustworthy Guards, Real Tests, Locked-Down Runtime Broker

## Summary

v1.8.0 is a correctness and hardening release. It removes three classes of
architectural drift that had accumulated behind passing checks: guard logic that
existed in three divergent copies, unit tests that verified private copies of
logic instead of the shipped implementation, and a native runtime broker whose
defaults allowed unauthenticated local process execution.

Nothing in the product surface was redesigned. The approval gate, credit
accounting, SSE delivery path, and task-scoped authorization are unchanged.

## Security

- **Runtime broker binds loopback only.** `native/runtime-broker` previously
  defaulted to `:4317` — every interface. `POST /v1/processes` starts an
  arbitrary local executable with a caller-supplied environment, so that default
  exposed remote code execution to anything routable to the host. The default is
  now `127.0.0.1:4317`, and a non-loopback bind is refused at startup unless
  `XEO_RUNTIME_ALLOW_PUBLIC=1` is set deliberately.
- **Process control requires a shared secret.** Every `/v1/processes` request
  must present `XEO_RUNTIME_TOKEN` as `Authorization: Bearer <token>` or
  `X-Xeo-Runtime-Token`, compared in constant time. When no token is configured
  the broker returns `503` for process control and serves only `/healthz` — it
  never runs unauthenticated. `/healthz` now reports whether process control is
  actually enabled.
- **Per-install token, minted by the desktop shell.** Electron generates a
  32-byte random token, stores it `0600` under `userData`, and passes it to both
  the broker and the Next.js server through the environment. It is never exposed
  to a renderer.

## Fixed

- **Guard logic had three copies.** The behavioral guards described in
  `AGENTS.md` §5.5 were inline literals in `runAgent`, duplicated on the
  `<action>` fallback path with a weaker 5-pattern question detector, and
  re-declared a third time in the test suite. Real autonomy violations slipped
  through on models without native tool calling. All detectors, thresholds, and
  nudge copy now live in `lib/agent/guards.ts`, imported by both dispatch paths
  and by the tests.
- **Two test files verified nothing.** `test/loop-guards.test.ts` asserted
  against its own inline pattern arrays, and `test/timeline.test.ts` defined a
  private `parseEvents`/`buildTimeline` that had already diverged from the
  component (it dropped the first message; the UI renders it). Both files would
  have stayed green if the implementation were deleted. They now import the
  shipped modules.
- **Timeline derivation extracted.** Run-boundary splitting, tool-event
  attribution per run, turn de-framing, phase derivation, and the status
  predicates moved from `TaskClient.tsx` into `lib/agent/timeline.ts`.
- **Nine silent `catch {}` blocks** violated rule 3 (no silent failures) — eight
  in `lib/agent/preview.ts` plus one each in `PreviewPanel.tsx`,
  `lib/agent/env.ts`, `desktop/electron/main.cjs`, and the browser-bridge smoke
  script. Every one now logs with context. Preview readiness failures include
  the failed-probe trail, so "no readiness signal" reports what was attempted
  and refused. `waitForApp` reports the last connection error on timeout.
- **Two mojibake artifacts** (U+FFFD where an em-dash belonged) in
  `lib/agent/loop.ts` and `lib/db/queries.ts`.
- **UTF-8 BOMs** were present in `package.json`, `package-lock.json`, and three
  route files. The BOM in `package.json` broke PostCSS config resolution and
  made the Vite-based test runner fail to start.

## Added

- **Role and workflow selection in the Workbench.** `agent_profiles` and
  `agent_skills` were persisted, validated by `POST /api/tasks`, compiled into
  run context, and rendered as "role active" / "workflow active" badges on the
  task header — but there was no control to choose them, so both were
  permanently `null`. The dashboard now offers both when enabled layers exist.
- **Credits spent on the task header.** The `credits` event was streamed every
  run and stored in React state that nothing rendered. Per-task cost is now
  visible where it is incurred, not only in the ledger.
- **Context token detail.** The `context` event's `used_tokens` and
  `context_window` were passed to the indicator and discarded; they now back a
  tooltip so the percentage is verifiable.
- **`npm run lint` is a real gate.** The script existed with no ESLint config, so
  it always passed. `.eslintrc.json` adds `next/core-web-vitals` plus
  `no-empty` with `allowEmptyCatch: false` — rule 3 is now machine-enforced. The
  tree is clean with zero warnings.
- **Broker tests.** Go coverage for the auth gate (missing, wrong, both header
  forms, and the no-token fail-closed path) and the bind guard (loopback
  detection, wildcard refusal, explicit opt-in).
- **CI runs the new gates.** Both release jobs now run `npm run lint`,
  `go vet ./...`, and `go test ./...`.

## Compatibility

Backward compatible. No schema migration, no config change required for the web
surface. Existing local settings and stored task data are preserved.

Desktop users: the runtime-broker token is minted automatically on first launch.
If you run the broker by hand, set `XEO_RUNTIME_TOKEN` or process control will
return `503` — this is intentional, not a regression.
