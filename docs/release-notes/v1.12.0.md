# v1.12.0 — The Agent Development Environment

## Summary

v1.12.0 turns the capability backends shipped in v1.11.x into a complete agent
development environment, and it closes with fixes for three defects that only
adversarial review and a real browser could find — including one where the unit
suite was green and the product was wrong.

The audit that opened this release re-verified every claim from scratch instead
of trusting prior reports. It found a complete MCP registry with **zero call
sites**: the schema, validation, connection pool, and agent dispatch existed,
but there was no route and no UI, so no user could ever add a server. It found
`git_status` and `git_commit` declared in the event registry with typed payload
readers — and never emitted by anything. And it found a Diff tab wired to state
no code path ever set. Three features that shipped as "done" were structurally
unreachable.

All three are end-to-end now, and the release adds the verification discipline
to keep them that way.

## Terminal: fixed where it actually broke

Three defects found by real-browser E2E, none reproducible from the unit suite:

- **Fast typing was corrupted.** Keystrokes POSTed as independent `fetch()`
  calls ride different keep-alive connections and can be applied to the PTY out
  of order. In the browser, `echo BROWSER_...` reached bash as `echoWO SER...`.
  Writes are now serialized through a promise chain, so byte order is exactly
  typing order.
- **A page reload leaked a live shell.** Full-page reloads run no React
  cleanup, and the idle reaper existed but had no caller — so every reload
  orphaned a PTY until the per-task cap locked terminals with a 429. The
  component now reconnects to the newest live session (scrollback survives the
  refresh) and deletes extras, and `createSession` reaps opportunistically.
- **`.bash_history` dirtied the workspace.** `HOME` points at the workspace by
  policy, so bash wrote its history into the task's repository, polluting
  `git status` on every session. `HISTFILE=/dev/null` keeps history out of the
  artifact under review.

Terminal opens, refusals, and user kills are now recorded as `terminal` task
events — a host shell on a task is governance-relevant history.

## MCP: the user surface

- `GET/POST /api/mcp/servers` and `PATCH/DELETE /api/mcp/servers/:id` —
  authenticated, rate-limited, delegating to the existing registry so there is
  still exactly one validation and tenancy path.
- **MCP Studio** in Settings: add, disable, and delete stdio servers. The copy
  states the boundary plainly: servers run as processes on this machine with
  your permissions; the agent can call them through the same approval gate as
  every other tool, but can never create, edit, or delete one.
- Registry tests now run against a real SQLite database and a **real stdio
  echo server** — handshake, namespacing, tool listing, tool call, and tenancy
  (a wrong user behaves exactly like a missing row), no mocks anywhere.

## Git: the rail and the events

- `git_status` and `git_commit` events are emitted for real, through an
  injected `GitEventSink` that keeps `git.ts` database-free for its direct
  unit tests. The commit hash in the event is cross-checked against
  `git rev-parse HEAD` in the test — not against our own output.
- `GET /api/tasks/:id/git` feeds a **Repository rail** in the governance
  column: branch or detached HEAD, dirty count, last commit, staged/unstaged/
  untracked. A workspace that is not a repository root renders an honest
  "not a repo" note — never an invented "clean" state.
- `GET /api/tasks/:id/git/diff` returns the unified diff the same `DiffView`
  renders for agent results. Traversal paths are refused with a `blocked`
  reason, not a 500.
- The **Diff tab works**: it seeds from persisted history, captures live
  `git_op diff` results, offers a workspace-wide diff, and makes each
  Files-changed row clickable for a scoped diff.

## Virtualization, not a cap

The Activity timeline previously truncated at 200 rows with a count of the
hidden remainder. `components/useVirtualList.ts` replaces the cap with real
windowing:

- Binary-search visible ranges over prefix-sum row positions.
- Per-row `ResizeObserver` measurement — a deep-mode row is ~7x taller than a
  compact one, and both must lay out correctly.
- The follow-bottom contract the run log already has: pinned to the newest
  while you are at the bottom, released the moment you scroll up.

Every row in a run's history is now reachable; the DOM stays bounded around
~25 rows. Browser-verified at 120+ events: 21 rows in the DOM at the top with
the oldest event reachable, 29 in the middle. The windowing math is unit-tested
directly, including the clamp for a stale scrollTop past the end of the list.

## Markdown and XSS

The renderer was rewritten: tables, blockquotes, ordered and nested lists,
`~~~` fences, horizontal rules, and safe links — the scheme check runs on a
control-character-stripped URL, because browsers ignore embedded tabs when
parsing (`java\tscript:` must not pass), and hrefs are quote-escaped against
attribute breakout. The escape-first invariant is unchanged and now pinned by
a 19-case XSS battery on top of 21 feature tests.

## Honest boundaries

- The test suite is hermetic: an ambient `DATABASE_URL` can no longer silently
  flip DB-backed tests onto PostgreSQL. Opting back in is explicit and
  documented: `XEOTEST_ALLOW_PG=1 DATABASE_URL=postgres://... npx vitest run`.
- Desktop packaging for Windows and the PowerShell shell path are exercised by
  the release workflow's own runners; the terminal fixes were browser-verified
  on bash.
- A real-model agent run remains the one layer this release did not exercise
  end-to-end; everything below the model call is.
