# Xeo Forge v1.4.0 — Local-First Agent Workbench

## Release overview

Xeo Forge v1.4.0 is a major 1.x milestone for the Local-First Agent Workbench. It combines the first desktop OTA foundation with Windows and Linux distribution, Intent-aware Chat/Work behavior, and selectable local Browser Profiles.

## Highlights

- **Desktop OTA foundation:** packaged desktop builds publish update metadata and artifacts through GitHub Releases.
- **Windows and Linux distribution:** Windows NSIS installer plus Linux AppImage and deb artifacts are published from the same release workflow.
- **Browser Profiles:** the optional Chromium extension announces a stable local browser identity and profile name. Xeo Forge can show connected browser profiles and lets the user select which connected browser Work should use.
- **No silent browser fallback:** if the selected browser disconnects, Browser Bridge does not silently redirect work to a different browser.
- **Intent-aware Work intake:** ordinary conversation remains conversational, while explicit work requests use the decision gate before direct execution or planning.
- **Local-first persistence:** the desktop Local Owner, SQLite database, project selection, settings, and task history remain in the local user data directory.

## OTA upgrade policy

**v1.3.1 is the minimum recommended installed version for receiving future OTA updates.** Users on v1.3.0 or older should install v1.3.1 or a newer release manually once before relying on OTA delivery.

We recommend always updating to the **latest available Xeo Forge release**. This keeps the desktop updater, Browser Bridge contract, security fixes, and release metadata on the supported path.

After an OTA update, users should verify that Xeo Forge opens normally and that their local project, settings, task history, Local Owner, and SQLite data are still present.

## Platform artifacts

- Windows x64: `Xeo-Forge-Setup-1.4.0-x64.exe`
- Linux x64: `Xeo-Forge-1.4.0-x86_64.AppImage`
- Linux x64: `Xeo-Forge-1.4.0-amd64.deb`

## Scope and limitations

This release does not yet include browser write-permission policy, domain allowlists, sensitive-action approvals, Strict Local redaction, code signing, or SmartScreen reputation work. Those remain planned follow-up work and are not implied by the presence of the optional Browser Profile connection.

Linux OTA is supported for AppImage installations when the application exposes the AppImage runtime path. The deb package is distributed as a Linux installation artifact; package-manager update behavior depends on the user's distribution and repository setup.

## Upgrade notes

The v1.4.0 release preserves the existing desktop user data location. Do not delete the Xeo Forge user data directory during upgrade. If an installer is shown during an update, record that behavior and report it as an OTA issue rather than deleting local data or reinstalling blindly.

## Verification

The release was built through the multi-platform GitHub Actions workflow and includes Windows and Linux artifacts with their corresponding update metadata. Real-device OTA verification remains a required operational check for each updater change.
