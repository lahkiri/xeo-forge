# v1.13.1 — The Terminal Actually Ships

## Summary

v1.13.0 installed on a real Windows machine answered the first terminal with:

```
Could not start a terminal: Failed to load native module: conpty.node,
checked: build/Release, build/Debug, prebuilds/win32-x64
```

Every release check had passed, because every release check measured the app
*booting* — none of them ever spawned a terminal inside the packaged runtime.

## Root cause

Two gaps, compounding:

1. **Next's standalone file tracer cannot follow node-pty's native loads.**
   They are resolved at runtime by path probing (`build/Release`,
   `prebuilds/win32-x64`), so the traced bundle carried the JavaScript and
   dropped the binaries. `scripts/prepare-desktop.mjs` already contained the
   fix for this exact defect class — for `better-sqlite3`, with a comment
   explaining why — written before the terminal existed. It was never
   extended when the terminal shipped.
2. **The desktop smoke test verified boot-level behavior only**: redirect,
   implicit owner, task creation, decisions, broker health. All green on a
   machine where the terminal was dead.

## The fix — closed at the class level, not the instance

- `prepare-desktop.mjs` rebuilds **both** native modules for the Electron ABI
  (`--only better-sqlite3,node-pty`), replaces the traced copies wholesale,
  and then **asserts the pty native binary exists in the bundle**. This
  defect class now fails the build, not the user's first terminal.
- `smoke-desktop.mjs` gains a real capability check: it creates a terminal
  session through the standalone server running under Electron, writes
  `echo XEO_PTY_SMOKE_<pid>` into the PTY, and requires the shell's echo on
  the SSE stream before passing — on both the Windows and Linux release
  runners, before any release can publish. The exact v1.13.0 failure cannot
  pass this pipeline again.

## Verification

```
Unit gates          32 files / 673 tests, tsc=0, lint clean, build=0
Local rehearsal     rebuild complete for both modules; standalone contains
                    build/Release/pty.node and prebuilds/win32-x64 (the exact
                    directory named in the error); prepare gate green
Release pipeline    real-PTY smoke runs in build-windows and build-linux;
                    publish blocked unless both pass
```

## Honest boundary

A pipeline can prove the capability works on GitHub's runners; only a real
install on a real machine closes the loop. If the terminal still fails
anywhere after this version, the error report will come from a machine the
pipeline could not see — send it in.


## Build note

The first v1.13.1 build attempt failed before publishing: electron-rebuild
3.7.2 bundles a node-gyp that cannot parse Visual Studio 18 on current
runners, so node-pty could not be compiled for the Electron ABI (the shipped
prebuilds are plain V8 addons and are not Electron-portable). @electron/rebuild
was upgraded to ^4.2.0 before this release published. The published artifacts
passed the real-PTY smoke gate on both Windows and Linux runners.
