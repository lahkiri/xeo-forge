# v1.11.0 — Runtime Made Visible

## Summary

v1.11.0 closes the gap between what the engine does and what the interface
shows. The audit that opened this release found a real bug, not a styling
deficiency: **both client SSE handlers carried hardcoded event-type arrays that
omitted the events v1.10.0 had just added.**

`context_layers` — the event proving which approved memories reached the prompt,
the signature trust feature of the previous release — was persisted, streamed
over SSE, and then silently discarded by the browser. Memory proposals never
surfaced. And because `ChatClient` subscribed to only four event types, runtime
state could never reach its "Reading project context" branch, so the truthful
runtime work shipped in v1.10.0 was partly inert at the UI layer.

The frontend was not merely under-designed. It was throwing away capability.

## Event registry

`lib/agent/events.ts` is now the single frontend/backend contract:

- All 21 event types declared once, each with a product-language purpose and its
  subscribing surfaces.
- `eventTypesFor('chat' | 'work')` replaces both hardcoded arrays.
- Typed payload readers (`readContextLayers`, `readToolCall`, `readContextUsage`,
  `readVerification`, …) so components stop indexing into `data` and guessing
  snake_case key names. Malformed rows are dropped rather than rendering
  `undefined`.
- `describeEvent()` is the one mapping from event to product language, so the
  timeline, the runtime banner, and the activity list cannot describe the same
  event differently.

`test/events.test.ts` **scans `lib/` and `app/` source for every
`emitTaskEvent` call site** and fails if a type is not declared. It also asserts
the scan matched more than ten sites, so it cannot pass vacuously. This class of
bug cannot recur silently.

Chat now subscribes to `tool_call`, `tool_result`, `context_layers`,
`compaction`, and `model_retry`. It deliberately does **not** subscribe to
`plan`, `verification`, or `todo_update`, because Chat cannot plan — and a test
asserts that.

## Execution timeline

A real Activity surface (`Cmd+2`), built from the persisted event stream:

- Every row comes from `describeEvent()`. Events with no standalone meaning
  (`text`, `reasoning`, `task_status`) render nothing rather than padding the
  list to look busy.
- Context compilation expands inline to name exactly which memories and
  instructions were injected, with scope and confidence.
- **Deep mode** shows raw event envelopes — seq, type, timestamp, payload — so
  developers get event internals without pushing them into the default view.
- Rows are capped at 200 with an explicit count of what is not shown, so a long
  run cannot stall the surface.

## Semantic primitives

`components/AgentPrimitives.tsx` replaces generic cards with components that
understand the domain: `AuthorityRow`, `RuntimeBanner`, `XeoFlow`,
`ContextBudget`, `CurrentTruth`, `ResultArtifact`.

Each renders only from supplied backend state, and renders **nothing** when a
value is absent rather than showing a placeholder.

`authorityForMode()` mirrors what `executeTool` enforces at dispatch. Tests
assert that it:

- locks write and execute outside build mode,
- always allows reading,
- never reports browser interaction as plainly `allowed` (it is `gated`, because
  interaction requires a separate policy grant),
- never describes restricted host execution as a "sandbox".

Every authority row carries a reason in its title, so "Why?" is always
answerable from real policy rather than a help page.

## Xeo Flow

A clickable Context → Plan → Approval → Execute → Result trail. `deriveFlow()`
marks a stage done only when the corresponding state is observable: a context
event, a stored plan, a frozen `approved_plan`, a `tool_call`, or a terminal
status. It replaces the previous `PhaseTrail`, which was closer to a step
counter.

A test asserts it does **not** claim Execute finished when no tool ever ran, even
on a completed task.

Each stage navigates to the surface that explains it, so the trail is navigation
rather than decoration.

## Run commands

`Cmd+K` gains run-scoped commands: open activity timeline, inspect effective
context, review memory, browse workspace files, open preview, copy run ID. Only
commands that actually exist are registered.

## Verification

- `npm run typecheck` — clean
- `npm run lint` — clean, zero warnings
- `npm test` — **265 passing**, up from 248 (41 new across the event registry and
  semantic primitives)
- `npm run build` — compiled successfully

## Documentation

`AGENTS.md` gains §15 (event registry contract) and §16 (UI truth rules), both
describing enforced behavior. §16 states plainly that a component lacking a
backend value renders nothing, that `deriveFlow` is not a step counter, and that
`ResultArtifact` must not display a verification fact for a run with no
verification event.

## Honest scope

This release fixes the plumbing and builds the primitives. It does **not**
complete a full visual redesign: the Work layout is still three panes with a tab
strip, Chat's visual language is unchanged, and the responsive and accessibility
passes are partial. Those need visual validation against a running application,
which is the correct next step rather than more unviewed markup.

## Compatibility

Backward compatible. No schema change, no API change. All existing tasks,
conversations, memories, and history render as before — with the events that were
previously dropped now visible.
