# Xeo Forge v1.7.1 — Model Reliability, Browser Preview & Workbench UX

Xeo Forge v1.7.1 is a reliability and usability patch for the Local-First Agent Workbench. It resolves a configuration trap that could make the desktop runtime use a placeholder key from SQLite, improves recovery from provider rate limits, makes Browser Preview exercise governed interactions, and gives first-time users a clearer path through the Workbench and Control Center.

## Highlights

- **Model configuration diagnosis:** placeholder credentials are recognized as invalid instead of appearing configured; API keys remain masked; Control Center includes a non-persistent connection test for the configured base URL and model.
- **Better 429 handling:** streaming requests classify provider errors, respect `Retry-After`, retry rate-limit and transient network failures with bounded exponential backoff, and surface retry progress in the task timeline.
- **Actionable error recovery:** authentication, rate-limit, missing-model, network, and setup errors now have distinct user guidance with a direct route back to Local model settings.
- **Real Browser Preview:** Preview can run navigation and read-page inspection, with optional click/type checks gated by interaction policy, domain allowlist, sensitive-action permission, and explicit confirmation.
- **Extension onboarding:** Control Center now explains Chrome/Chromium installation step by step: `chrome://extensions` → Developer mode → Load unpacked → `desktop/browser-extension` → bridge token and Connect.
- **Workbench UX:** brighter layered surfaces, a clearer first-run empty state, starter actions, explicit Chat versus Work guidance, and a project-folder guard before local Work execution.
- **Task UX:** clearer loading and recovery states, stable latest-error display, and a settings CTA for model failures.
