# v1.14.0 — Trustworthy Speed

## Summary

v1.14.0 is a five-front release: a deep clean that turned one piece of dead
code into a missing lifecycle guarantee, a competitive analysis that fixed the
product's position against OpenHands' pivot, parallel read-only execution for
the agent loop, a capability-forward front door, and a README that finally
leads with the product instead of its changelog.

## The cleanup found a bug wearing a function's clothes

`killSessionsForTask()` carried the doc comment *"Called when a task reaches a
terminal state"* — and had **zero call sites since inception**. A completed or
failed run could leave its terminal sessions alive until the idle reaper
noticed. It is wired now, from both terminal paths, and a test pins both
wiring points. Dead exports (`getAllPreviews`, `mcpConnectionCount`,
`killAllSessions`) were removed; stale working notes moved to
`docs/archive/`; the superseded `verify-pty` script is gone (the release
smoke gate replaced it).

## OpenHands pivoted. We didn't blink — we sharpened.

`docs/competitive/openhands-analysis.md` dissects their Agent Canvas
repositioning: orchestrate many agents (Claude Code, Codex, ACP) across
local/Docker/VM/cloud, with automations. Their control is WHERE agents run;
ours is WHAT agents may do. Their own quickstart warns *"the agent will have
full access to your filesystem"* — that sentence is our pitch. The analysis
ends with an explicit do-not-chase list (multi-agent orchestration,
automations, cloud backends) so the governed-depth position stays ours:
**they optimize for running many agents; we optimize for trusting one.**

## Parallel read-only execution

Frontier models batch inspections ("read these five files, then git status").
Sequential reads were pure wall-clock loss. When every call in a turn is a
parallel-safe read — `file_read`, `file_list`, or a git read op — credits
debit in order, `tool_call` events emit in order, the reads run concurrently
(cap 6), and results emit in CALL order: the audit stream stays deterministic
whatever order the reads complete in. Any mixed batch, and anything mutating,
external, or MCP, stays sequential — the whitelist is pinned by tests that
fail if a write-capable tool ever qualifies.

## The front door says what the product is

The Work intake now carries a capability strip — Files, Git, Terminal, Diff
review, MCP tools, Preview, Browser — ending with the contract chip: *"Every
write behind your approval."* Eight chips, each a capability wired
end-to-end, stated where every run begins.

## Docs that match the product

Nine "What changed" sections moved from the README to `docs/RELEASES.md`; the
README now leads with identity, a capability/who-decides table, market
positioning, and runtime guarantees updated for what v1.13/v1.14 actually
enforce (terminal cleanup on run end, tier-adaptive guards, parallel reads
with a deterministic audit stream).

## Also in this release

- Strong-model patterns extended: **GLM-4/5 and Kimi K2+** map to the
  permissive guard profile (GLM-3 stays standard).
- A loop-guards test written for the two-path loop **correctly failed when
  the third path arrived** — updated to the new reality. The suite does what
  the owner warned it must: catch the project outrunning its tests.
- Dev gotcha documented: after `prepare-desktop` leaves Electron-ABI natives
  in `node_modules`, `npm rebuild better-sqlite3 node-pty` restores the
  host-ABI build for the unit suite.
