# v1.16.0 — The Real-Model Release

## Summary

The first real-model run (Claude Opus 5, field-tested by a friend of the
owner) produced the most valuable bug report in the project's history: the
agent repeated its message three times. The evidence was in the transcript
itself. The root cause was ours — three compounding layers, all fixed —
plus the field report's second ask: reasoning models' thinking was never
shown.

## The repetition chain (diagnosed from code)

1. Opus answers a question in full prose after testing tools (correct).
2. The text-termination guard nudges "call task_complete" → the model
   re-emits its entire answer plus the call.
3. The summary-section gate retries "rewrite the summary" → it re-emits
   the answer again.
4. `finalizeComplete` persists the summary as yet another message.

Three visible copies. The model was obedient; the prompts never told it
the user had already read the answer.

## Fixes

- **Both nudges forbid repetition** and demand a SHORT engineering-memory
  summary ("the summary is engineering memory, not a second delivery").
- **`summaryRestatesPrevious()`** — finalizeComplete skips persisting a
  summary that restates the last assistant message (exact / containment /
  60% shingle overlap). The memory still lives in the task_complete
  events; only the duplicate delivery dies.
- **ThinkingBlock** — the loop has always emitted `reasoning` events and
  no component ever rendered them. A reasoning frontier model's thinking
  is now visible: collapsed by default, live-pulsing while streaming,
  expandable to the full monospace thought, on both Chat and Work.
- The reported "message streaming flow" complaint is addressed at its
  root: the repeats WERE the bad flow.

## Honest boundaries

- The Windows-environment notes from the field report (POSIX commands
  failing in `code_execute`, `cd` restrictions) are documented behavior of
  restricted host execution on Windows — the tool descriptions now carry
  clearer platform guidance in a follow-up, and the shell is PowerShell.
- Guard tuning now has one real transcript of evidence; each further
  flame-test run tunes them with data, not guesses.
