# v1.19.1 — The Answer Keeper

## Summary

Fixes the worst live-reported defect: **chat mode was losing the real
answer**. Evidence task `6350ea92`: a user sent "اهلا", the model streamed
169 text deltas — 2,405 characters of genuine Arabic answer — then called
`task_complete` with a 247-character procedural summary. That summary
replaced the streamed answer in both the visible chat and persisted
history. Root cause was three layers agreeing on the wrong contract.

## The three-layer fix

1. **Chat gets its own prompt contract.** Chat previously reused the
   build-oriented `AGENT_SYSTEM_PROMPT`, which instructs: "the only valid
   output is tool calls and the final task_complete summary." A compliant
   model therefore answered in prose, then buried it. New
   `CHAT_SYSTEM_PROMPT`: the streamed reply IS the deliverable; tools are
   read-only helpers; no completion theater.
2. **The verbatim answer is persisted.** `chatTextBuffer` accumulates chat
   deltas across iterations; every `finalizeComplete` termination path
   passes it as `chatProse`; chat persists whichever is richer (the prose),
   with the existing anti-duplicate guard still applied.
3. **No terse duplicate bubble.** The client's `done` handler skips a
   summary that is already contained in the text the user just watched
   stream — the summary remains available in the run metadata without
   double-posting.

## Also in this release

- **Ctrl+K searches sessions** as its placeholder always promised: the
  palette now lists recent chat sessions and work runs ("Open chat
  session" / "Open work run") alongside commands.
- **Professional icon set**: unicode glyph "icons" (▶ ↗ ⌁ ◇ ⌄) in the
  unified workspace replaced with inline stroke SVGs (Lucide geometry,
  zero new dependencies).
- **Empty-state rhythm tightened**: transcript padding reduced
  (4.75/9rem → 2.5/2.75rem), welcome margin 3.75 → 2.25rem — the composer
  no longer lands below the fold on common window heights.
